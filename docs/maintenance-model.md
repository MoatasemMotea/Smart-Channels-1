## 1. The contract

The finished website must not depend on Claude — or any specific person or
vendor — for ordinary maintenance. The owner has full ownership and
editability of source code, content, statistics, images, videos, projects,
gallery, clients, alliances, navigation, contact information, and
translations.

**Core rule:** routine business-content changes are edits to obvious
structured files (`src/content/`, `src/messages/`, `public/`), never to
React presentation components. If a routine change ever requires touching a
component, that is an architecture defect to be fixed, not a workflow to be
documented.

No CMS at this stage (A-006). No proprietary visual builder. No vendor
lock-in: the stack is standard open-source (Next.js/React/TypeScript), the
content is plain typed data in the repository, and the code must remain
understandable and maintainable by any competent developer.

## 3. The owner editing workflow (intended shape)

1. Open the relevant file under `src/content/` — each file starts with a
   comment explaining exactly what may be edited and how.
2. Make the change. Content files are data literals only — no logic, no
   React, no imports beyond types.
3. Run the documented validation (and media utility when adding media). A
   mistake fails loudly with a readable message (Q6): broken path, missing
   required field, unknown category, missing Arabic (A-002 rules).
4. Build and view locally. Done.

Adding gallery media, end to end (A-005): **add file → add small metadata
entry → run documented utility if required → build.** Never React edits,
never manual dimension measurement.

## 4. Localization maintenance

- Business content: `en` is the approved source; `ar` is added on the same
  record — facts are never duplicated across locales.
- `arPolicy: 'latin'` marks proper nouns whose official form is Latin
  (valid, complete — A-002 exception).
- Development builds list every English fallback as a visible warning;
  release validation blocks on missing required Arabic business copy
  (A-002). The owner can always see exactly what remains untranslated.
- UI strings: keep `en.json` / `ar.json` keys in parity; validation reports
  drift.

## 6. Boundaries that make this durable

- **Accessor boundary (A-006):** components consume content only via
  `src/lib/content/` accessors, which also enforce publish filtering
  (A-004). A future CMS swaps accessor internals; components, schemas, and
  this task→file contract survive.
- **Content provenance:** everything in `src/content/` traces to the
  approved Company Profile, a logged owner decision, or an owner-supplied
  asset. C-001 stays out of public content until resolved.
- **Presentation isolation:** design changes (P2+) may not introduce
  hard-coded business facts into components. Statistics, names, counts, and
  contact details render exclusively from the content layer.
